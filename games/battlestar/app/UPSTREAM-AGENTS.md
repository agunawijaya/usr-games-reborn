# AGENTS.md — `battlestar / fancy-web` (*Battlestar — Pajamas to Paradise*)

Port-level instructions. Read the game-level [`../../AGENTS.md`](../../AGENTS.md)
and the root [`../../../../AGENTS.md`](../../../../AGENTS.md) first.

## Identity

**fancy-web**: a faithful engine under a procedurally generated
presentation. The game is the 1979 program's, byte for byte; the
pictures and sound are free, but only ever derived from its state.

## Hard rules for this port

1. **The C source is the truth, not the canonical docs.** They were
   wrong in 29 places ([`docs/notes.md`](./docs/notes.md) §2). Cite
   `file.c:line` for anything ported; never copy C into the repository.
   Propose canonical fixes in `docs/notes.md` §3; do not edit
   `bsdgames/battlestar/docs/` from this port.
2. **The engine stays faithful and pure** (`src/engine/`): no DOM, no
   clock, no `Math.random` (glibc `random()` only, `rng.js`). `npm test`
   must keep reproducing the 22 golden transcripts of the real binary.
   Re-capture them with `npm run golden` (WSL/Linux + `bsdgames` +
   `gcc`); never edit a `.out` by hand.
3. **Every deliberate difference from the C** is listed in
   [ADR-010](./docs/decisions/010-engine-deviations.md); anything new
   needs an ADR with Options Considered.
4. **Override flags default off and stay invisible when off:**
   `tests/overrides.test.js` replays every golden script with all flags
   false. Any flag or action sets `cheated`.
5. **Zero raster assets** ([ADR-002](./docs/decisions/002-zero-raster-assets.md)):
   no image or audio files, no `data:image`, no loaders. Canvases and
   render targets filled by code are fine. `npm run check:raster`.
   Screenshots belong in `media/` only.
6. **Nothing decorative touches the engine.** Scenes come from
   `composeRoom()` (pure) and engine events. Spacecraft stay original
   designs; people stay non-explicit silhouettes (ADR-009).
7. **Visual changes are screenshotted and critiqued** before they land
   (`node scripts/shots.mjs <dir> name=room,night,facing:e,time:N,dark,items:12`
   with `SCENE=1`, then `node scripts/contact.mjs <dir> <out.png> 4`);
   record what was wrong and why in `docs/notes.md` §7. Shoot day and
   night, and several rooms per biome — watch for sameness.
8. **Keep every rung of the quality ladder working** (ADR-011): run
   `GPU=swiftshader node scripts/perf.mjs` after rendering changes and
   update the README's table if the numbers move; `npm run smoke`
   checks text mode.
9. Zero build: vanilla ES modules; Three.js is vendored.

## Where things are

- Engine: `src/engine/` — `battlestar.js` (the game), `data/world.js`
  (generated by `scripts/extract-data.mjs`), `rng.js`, `flight.js`
  (fly.c), `planner.js` (hints), `autoplay.js`, `run.js`.
- Scene spec: `src/scene/composer.js`, `layout.js`.
- Rendering: `src/render/stage.js` and `kits/` (one per biome), shared
  `materials.js`, `terrain.js`, `water.js`, `flora.js`, `people.js`,
  `craft.js`, `cockpit.js`, `post.js`, `env.js`, `sky.js`, `fx.js`.
- Page: `src/ui/` (`app.js` boot and wiring), `src/audio/audio.js`,
  `index.html`.
- Tests: `tests/` (node); `scripts/ui-smoke.mjs` (browser).
- Architecture: [`docs/architecture.md`](./docs/architecture.md).

## Debug hooks and URL parameters

`window.__bs` (for scripts only): `game`, `stage`, `send(line)`,
`place({ room, night, facing, items, worn, dark, time, rested })`,
`teleport(room)`, `refresh()`, `spec()`, `mapPoint(room)`, `sound()`,
`play(recipe)`. URL: `seed`, `fresh=1`, `autostart=1`, `wizard=1`,
`user=`, `q=high|low`, `hc=1`, `motion=reduce`, `autodelay=ms`
(autoplay speed, used by the smoke test).
